# 실행 구조

`runtime.py`는 기존 Phase56의 keys/reset/policy/transition 함수를 재사용한다. 기존 다른 연구 폴더에 연결되던 로딩 부분을 동봉한 소스와 모델 기준으로 바꿨다. `instrumented_logic.py`는 원래 감사 전이와 같은 원본 엔진의 중간값 반환본이다. 원본 전이와 전체 다음 물리 상태·관측·보상·종료가 같은지 `verify.py`가 검사한다.

PPO는 1345차원 공개 관측을 Dense512→GRU512로 인코딩하고 Actor/Critic을 분리한다. 이전 행동이나 숨겨진 전체 지도를 추가 입력하지 않는다. M2 Mask를 적용한 17개 행동 분포에서 고정 RNG로 샘플한다. 개입 중에도 실제 새 관측으로 PPO carry를 갱신한다.

Skill은 공개 grid CNN과 관측·Mask·공개 목표 조건·경과 시간을 GRU128에 입력한다. PPO와 가중치를 공유하지 않는다. 최대 16 Primitive를 실행하고, 공개 설비 공동 접근 조건을 만족하거나 제작 제안·자원 손실·사망 등에 도달하면 PPO로 반환한다. 종료 head 자체가 모든 조건에서 실행 종료를 결정하는 것은 아니다. 구체적인 조건은 `gated_execution.py`를 따른다.

| 모드 | 실행 구조 |
|---|---|
| B0 | 동결 M2 PPO 단독 |
| G0 | 첫 공개 후보에서 동결 Skill 시작 |
| G1 | 공개 Planner의 시작 가능성 검증 후 Skill |
| G2 | 동결 관측 분류 head의 시작 판단 |
| G3 | 첫 후보 후 16스텝 기다린 뒤 시작 |
| RULE | 공개 자원 여유를 반영한 결정적 시작 조건 |
| AUTO | 보존된 실행 효과 모델의 자원 하한으로 시작 조건 계산 |
| A1 | 공개 Planner가 접근·설치만 수행 후 PPO 반환 |
| C2 | 공개 Planner가 접근·설치·첫 도구 제작까지 개입 |

RULE과 AUTO는 현재 철 과제에서 같은 결정을 내리는 것으로 기존에 확인됐다. 두 이름의 성능을 독립적인 두 성공 방법처럼 세지 않는다. Planner 비교는 추론 시 추가 탐색 계산을 사용하며 Skill과 계산 비용이 같다고 가정하지 않는다.

`run.py`는 저장·집계 어댑터다. 16스텝 scan을 사용하는 Skill 경로와 호스트 기반 Planner 경로를 보존한다. 비활성 패딩의 환경 호출도 실제 계산량에 포함하되 해당 보상을 정상 에피소드 Return에 넣지 않는다. 10000스텝 전에 종료한 정상 에피소드의 보상 합이 주지표다.
